1. [must-fix] `src/cloudflare_mcp/tools/__init__.py:35-44` (root cause: `src/cloudflare_mcp/server.py:47`, `src/cloudflare_mcp/client.py:45-57`) — every tool call leaks an unclosed `httpx.AsyncClient` / connection pool. `_client_factory()` (`server.py:40-47`) builds a brand-new `CloudflareClient(token)` per tool invocation; since it is called with `http_client=None`, `CloudflareClient.__init__` (`client.py:45-52`) sets `self._owns_client = True` and opens its own `httpx.AsyncClient` with its own connection pool. `CloudflareClient.aclose()` exists (`client.py:55-57`) specifically to release that client, but `run_tool()` (`tools/__init__.py:28-44`) never calls it on any path — not on success, not when `body(client)` raises `ToolError`, not on the generic `except Exception`. httpx does not auto-close a client when it goes out of scope (no `__del__`-driven cleanup); nothing in this code path ever calls `aclose()`, so every single `cloudflare_*` tool call permanently leaks one open connection pool (TCP sockets to `api.cloudflare.com`) for the life of the process. This service is specifically designed to be one long-running container serving every tenant's requests (Tech design "Multi-tenant isolation"), so this is not a cosmetic issue: under real traffic it accumulates open file descriptors/sockets without bound until the process hits its FD limit and starts failing (`OSError: [Errno 24] Too many open files`) or exhausts ephemeral ports — an outage caused purely by normal request volume, not by any Cloudflare-side condition. None of the 18 tests catch this because they inject a mocked `http_client` via `CloudflareClient(token, http_client=...)` (see `tests/conftest.py`), which takes the `self._owns_client = False` branch and is never subject to the leak. Fix: in `run_tool()`, wrap the body call so the client is always closed exactly once (e.g. `try: result = await body(client) ... finally: await client.aclose()`, guarding the `client is None` early-return), or have `_client_factory()`'s caller manage the `CloudflareClient` with `async with`.
